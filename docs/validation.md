# 验证记录（2026-10-19）

本仓库按轻量布局提供原创原生源码、固定依赖获取脚本、接口和许可；不提交上游源码树、缓存或二进制。OpenVPN 3.11.7 与 Asio 1.24.0 的固定归档均经过 SHA256 验证，获取脚本也固定 OpenSSL/LZ4/Asio 的归档 SHA256。损坏缓存必须在解压之前失败。

## 本地验证

- 独立仓库可构建 HarmonyOS arm64 原生库；不依赖旧工程的绝对路径。Bash 和 zsh 均能从任意仓库位置加载环境脚本。
- 即使先加载了交叉编译环境，Host 测试仍使用 `HOST_CXX` 对应的本机编译器。
- 四组 C++ 回归通过：配置与认证解析、路由补集、会话生命周期、真实压缩解压。
- 真实压缩向量覆盖 LZO、LZO-swap、LZ4、LZ4-v2；检查正确内容、保持不压缩上行、截断及解压溢出，共 16 个检查。Host 不链接外部 LZO。
- 依赖完整性回归 3 项通过：获取脚本、OpenVPN 缓存、Asio 缓存损坏均被 SHA256 拒绝。
- 许可证头及组件清单检查通过；应用许可资源由外部应用单独做同步检查。
- 独立测试服务端的构建脚本在空临时目录验证通过，兼容本机 Python 3.9；服务端只替换 macOS TUN 适配，不修改其压缩或 TLS 代码。

## 配套应用集成验证

这些检查在外部 ArkTS 应用中执行，应用源码和 test HAP 不在本仓库中；不能把此处的应用测试描述当作克隆本仓库即可运行完整应用。

- 生产 ArkTS 适配器故障注入 9 项、文件错误 7 项、控制通道准备 5 项、许可资源与无损段落重排 9 项通过。
- 真机 Native/TUN/存储回归 10 项；真实本地服务端互通 30 项；实际压缩隧道回归 3 项通过。
- 实际下行 IP/TCP 数据从 1220 字节压为 LZO 158 字节、LZ4 142 字节、LZ4-v2 142 字节；手机外部浏览器接收后返回 TCP ACK。证据只统计本次探测期间的压缩日志，普通未压缩包或之前探测的日志不能使测试通过。
- 应用明暗主题均验证了设置入口、六个离线许可证全文、原生返回导航和指定源码地址。
- 原生完整符号表有 Core 内置 LZO 解压器，无外部 liblzo 符号。Native 与应用构建日志未出现警告。
